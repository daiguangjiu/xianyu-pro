## 二、问题明细（现状 → 为什么是问题）

### 1. 毛利口径两套（高）
- 现状：`app/models.py:411` `Order.net_profit = sale_amount − 成本 − 运费 − 平台技术服务费`；`app/services/finance.py:79` `paid = deal_amount or sale_amount` 再算毛利。
- 问题：有成交价（deal_amount ≠ sale_amount）的订单，**订单列表/详情页的毛利与资金页的毛利是两个数**，运营对账时必然打架。渔货栈订单页读的正是 `hub.net_profit`（`src/web/hub_orders.py:53`），所以两端页面都受影响。

### 2. 时间口径三套（高）
- 现状：① `app.timeutil.now()`（北京 naive）—— 渔枢系统端、渔货栈采购域/铺货；② `datetime.now(timezone.utc)`（UTC aware）—— `src/web/router.py`(3 处)、`src/goods/*`、`src/merchant/service.py`(8 处)、`src/channel_xianyu/*`、`src/logistics`；③ `datetime.now()`（本地 naive）—— `src/order/state.py:243`（订单流转时间戳）、`src/goods/service.py:49/72`（商品编码/SPU）。
- 问题：容器时区为 UTC 时，②③ 与 ① 差 8 小时 → 渔货栈订单的确认/发货/完成时间、商家入驻审核时间、商品同步时间与渔枢系统侧时间对不上；aware 与 naive 混在同一张表，排序/区间筛选都不可靠。

### 3. 状态回写覆盖不全（高）
- 现状：`app/services/self_sync.notify_self_fulfillment` 只在 `app/web/pages.py:1367`（订单编辑保存）调用一次；`src/order/hub_sync.sync_from_hub` 只处理 ① 物流单号→已发货 ② 渔枢系统已退款/关闭→退款收尾 ③ 渔枢系统撤单→取消。
- 问题：
  - 渔枢系统侧其它改状态的入口（`app/services/order_state.py` 的 derive、群消息解析识别退单、推单页、物流单号维护页）**都不触发回写** → 群里识别出退单，渔货栈还是「已发货」；
  - 反向：渔货栈 `flow.apply_action` 只在 `push_hub` 时调渔枢系统（退款、取消、确认收货、标记异常**都不回传**）→ 渔货栈已退款，渔枢系统侧订单还停在「已发货」；
  - 渔枢系统没有「已完成」状态（见 5），所以正向收尾回写本来也无处可落。

### 4. 商品删除 / 上下架不联动渔货栈（高）
- 现状：`app/services/product.py:1083` `delete_product` 只解绑订单、删规格、删商品；`set_listing`（1091）只改渔枢系统自己的 `status`。
- 问题：渔枢系统商品被删除后，`supplier_items` 里那条 `hub-prd-<id>` **仍在售**，且渔枢系统侧再也无法管理（「下架/更新资料」入口随商品一起没了）→ 渔货栈里出现无人认领的孤儿货源，分销商还能下单。

### 5. 渔枢系统订单缺正向终态「已完成」（中）
- 现状：`app/models.py:35-74` 状态只有 new / pushed / shipped / refund_* / closed / canceled，没有 completed；渔货栈有 completed（`src/order/state.py:30`）。
- 问题：发货之后正向流程就停住，无法记录「买家签收 / 交易成功」，结算侧也分不出「在途未结」与「可结」，跨端状态映射缺一环。

### 6. 渔货栈采购付款在渔枢系统侧无痕迹（中）
- 现状：`app/services/dso_sync.py:89` `_cost_of` 取 `PurchaseOrder.cost_price`（老的 1688 代发链路）或 `item.cost_price`；新采购域 `stock_orders`（`src/self_purchase/order.py`）**没有任何回写**。
- 问题：渔货栈下单付款（模拟支付）后，渔枢系统订单成本、资金流水都没有对应记录 → 同一笔交易在渔货栈有采购单、在渔枢系统侧查无此款。

### 7. 渔枢系统改资料 / 改库存不回传渔货栈（中）
- 现状：`sourcing_publish.publish` 只在点击「上架/更新资料」时同步一次，且会用渔枢系统侧现值覆盖渔货栈。
- 问题：① 改了标题/价格/图之后渔货栈还是旧的，运营不知道要重发；② 反向风险更大——渔货栈若手工调过资料，渔枢系统再点「更新资料」会被悄悄覆盖。

### 8. 上架时多规格与渔货价丢失（中）
- 现状：`sourcing_publish.py:339-349` 无论渔枢系统商品有几个规格，`sku_list` 只造一条 `默认`，价格取 `product.price`（建议售价），库存取商品总库存。
- 问题：多规格商品在渔货栈只剩一个「默认」规格；SKU 价用建议售价而不是渔货价，与「渔货价＝渔货栈成本价」的口径冲突（采购车取的是 SKU 价）。

### 9. 两套铺货记录（中）
- 现状：`ChannelListing`（我的上架 /self/selection，闲鱼发布记录，带 source=handoff/draft/selection）与 `ShopGoods`（店铺商品池 /self/shop-goods，带素材下载）是两张表、两个入口。
- 问题：对分销商而言「我要卖这个货」被拆成两步两份记录，状态互斥也不互通（进了池 but 没铺货 / 铺了货 but 不在池），页面无法给出一致的「这件货我处理到哪一步」。

### 10. 平台技术服务费（中）
- 现状：`sync_service_fee` 只在 `platform_fee == 0` 时落金额，之后改价不重算；`order_amounts` 里 `service_fee_rate_for` 不传 shop 就恒用默认 0.6%。
- 问题：成交价被修正后手续费停留在旧值（页面仍显示「按 0.6%」），与订单实际金额不符。

### 11 ~ 14（低）
- 11：`src/web/hub_orders.py:63` `HUB_STATE_LABELS` 里的 `done/cancelled` 两个键**在渔枢系统状态集里不存在**，而 `refund_request/refund_synced/refunded/closed/canceled` 没配文案 → 渔货栈订单页直接显示英文原值。
- 12：渔货栈没有资金视图，采购单付了多少钱只能进 `/self/purchases` 看单，看不到流水与核销。
- 13：货源被渔枢系统下架后，已在采购车 / 店铺池里的那件货没有「已下架」提示（加购与结算有拦截，存量没有）。
- 14：渔货栈「异常单」是渔货栈独有状态，渔枢系统侧看不到，运营两边对不上。

## 三、需求清单（每条给方案与验收，供决策）

### P0-1　统一毛利口径
- 方案：毛利只留一个实现——`finance.order_amounts()` 作为唯一口径（`paid = deal_amount or sale_amount`）；`Order.net_profit` 改为调用它（或删除该属性，页面/接口统一取 `finance`）。渔货栈 `hub_orders._brief` 的 `net_profit` 同样改为由 `finance` 算。
- 影响面：渔枢系统订单列表 / 详情、渔货栈订单列表 / 详情、资金页、看板毛利统计。
- 验收：造一单 deal≠sale 的订单，四处显示的毛利完全一致；`tests/test_finance.py` + 新增跨端断言。

### P0-2　统一时间口径
- 方案：全局只留 `app.timeutil.now()`（北京 naive）。批量替换 `src/` 里的 `datetime.now(timezone.utc)` 与 `datetime.now()`；`src/order/state.py::_now()` 直接改调 `app.timeutil.now`；`DateTime(timezone=True)` 的列（`shop_credentials.expires_at`）单列评估。
- 验收：新增断言「所有写时间的地方不出现 timezone.utc」的静态检查用例；页面上同一笔单的渔货栈/渔枢系统时间一致（差 ≤1 秒）。

### P0-3　补齐双向状态回写
- 方案：
  - 渔枢系统→渔货栈：把 `notify_self_fulfillment` 从「订单编辑保存」扩到所有改状态/物流/退款的入口（`order_state` 变更、群消息识别退单、推单、物流单号维护、退款收尾），统一封装成「订单事实变更后触发一次回写」；
  - 渔货栈→渔枢系统：`flow.apply_action` 在 refund_request / refund_finish / cancel / complete 时回调渔枢系统（新增 `notify_hub_fulfillment`），渔枢系统侧落到 `refund_status` / `canceled` / 新增的 completed；
  - 回写仍保持幂等 + 异常全吞。
- 验收：渔货栈点退款 → 渔枢系统订单出现退单状态；渔枢系统群里识别退单 → 渔货栈自动进入退款中。

### P0-4　商品删除 / 上下架联动渔货栈
- 方案：`delete_product` 删除前先把对应的 `supplier_items` 置为下架并写快照（理由「渔枢系统商品已删除」），或直接删除该条货源（二选一，建议前者，保留历史）；`set_listing(False)` 同步调 `sourcing_publish.unpublish`。商品详情页与渔货栈发布页给出「已删除」标记。
- 验收：删一款已上架商品 → 渔货栈该货源下架且首页搜索不到；发布管理页无残留「已上架」。

### P1-5　渔枢系统订单增加正向终态「已完成」
- 方案：新增 `ORDER_STATE_COMPLETED = "completed"`（成交/签收后），进 `ORDER_STATE_CHOICES` 与正向统计；物流轨迹查到「已签收」自动落，或运营手工「确认收货」；结算侧区分「已发货在途（不可结）」与「已完成（可结）」。渔货栈 completed ↔ 渔枢系统completed 双向映射。
- 验收：一单走完 pending→completed，两端状态一致；资金页能把在途单排除在「可结」之外。

### P1-6　采购域与渔枢系统资金打通
- 方案：采购单支付成功 → 在渔枢系统侧生成一笔 `SETTLEMENT_SUPPLIER`（应付，对象＝平台/供应商）流水，或至少把采购金额回填到对应渔枢系统订单 `cost_amount`；`_cost_of` 增加 `stock_orders` 来源。
- 验收：渔货栈下一笔采购单并支付 → 渔枢系统资金页出现对应应付流水（或在途标记）。

### P1-7　商品资料 / 库存变更回传（含冲突提示）
- 方案：渔枢系统商品保存时，若已上架渔货栈则自动同步（默认开，可在发布页关）；渔货栈侧手工改过的字段标记为「本地改写」，渔枢系统覆盖前提示。渔货栈发布页对「渔枢系统已改、渔货栈未同步」的商品打「资料已过期」标。
- 验收：改标题/价格 → 渔货栈同步更新；未同步时列表有「已过期」提示。

### P1-8　上架时按真实规格生成 SKU
- 方案：`publish` 用 `ProductSku` 生成 `sku_list`（规格名 / 渔货价 / 库存 / 编码），没有规格时回落单条「默认」，价格取**渔货价**口径（与采购车一致）。
- 验收：三规格商品上架后，渔货栈 SKU 表三条、价格与渔货价一致。

### P1-9　铺货记录合并口径
- 方案：明确「店铺商品池＝待处理/草稿，我的上架＝已发布」，`ShopGoods.status` 与 `ChannelListing` 建立 item_id 级关联；详情页两个按钮状态互认（已发布则池内标「已铺货」，移出池时提示已有发布记录）。
- 验收：同一件货在两个页面的状态描述不矛盾；入池/发布/移出链路幂等。

### P1-10　平台技术服务费跟随改价
- 方案：`sync_service_fee` 增加「金额与现算值不一致且非人工改过」时重算（用「人工改过」标记区分）；`order_amounts` 内部按订单 `xianyu_account` 取店铺费率，不再依赖调用方传 shop。
- 验收：改成交价后手续费同步变化；店铺设了 1% 的费率，页面按 1% 显示。

### P2-11　渔货栈渔枢系统状态文案对齐
- 方案：`HUB_STATE_LABELS` 直接复用 `app.models.ORDER_STATE_LABELS`（不要另抄一份），删掉不存在的 `done/cancelled`。

### P2-12　渔货栈只读资金视图
- 方案：渔货栈新增「我的资金」页（只读渔枢系统`settlements` + 采购单），或明确「资金归渔枢系统」并在渔货栈加跳转。

### P2-13　下架货源的存量提示
- 方案：采购车 / 店铺池 / 我的上架对 `unlisted_at` 非空或 `is_listed=False` 的货打「已下架」标并给出「看下架前的样子」。

### P2-14　异常单跨端可见
- 方案：渔货栈标异常时回写渔枢系统订单（备注 / 新增「异常」标记），渔枢系统订单页能看到；异常解除再回写一次。

## 四、建议排期

- **第一批（P0）**：P0-1 毛利、P0-2 时间、P0-3 回写、P0-4 删除联动 —— 都是「账与状态正确性」，建议一次性做完并补回归用例。
- **第二批（P1）**：P1-5 终态与 P1-6 采购打通建议同批（都动订单/资金），P1-7/8 商品同步与 SKU 同批，P1-9/10 收尾。
- **第三批（P2）**：文案与体验补齐。

> 说明：以上每条都可独立上线；若只想先解决「钱和状态」，做第一批即可。
