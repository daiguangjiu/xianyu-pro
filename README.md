# 小渔数科闲鱼订单渔枢系统平台

把飞书群里人工同步的闲鱼订单（固定模板文本 + 订单截图），自动变成结构化订单台账，
再按供应商组批推单，并为后续的资金数据分析留出数据底座。

```
飞书群 ──► 消息接入（事件回调 / 轮询拉取）
            │
            ├─ 文本解析（规则引擎：标签匹配 + 正则）
            ├─ 截图归档 + OCR（订单号、买家、成交价只在这里）
            ▼
        订单台账（去重、待人工确认队列）
            │
            ├─ 供应链推单（按供应商组批 → 导出 CSV/Excel → 状态回写）
            └─ 资金分析（销售额 / 成本 / 毛利 / 出货闲鱼号 / 回款支付宝归属人）
```

## 当前群消息模板

```
产品：亚朵四代单枕头

收货人:贲
手机号码:14790021215
地址信息: 安徽省 滁州市 琅琊区 清流街道 滁州市琅琊区凤凰湖畔18栋
备注： 要黑色，尽快发货
                                                             售价：115
出货闲鱼号：卖货的小姑娘
回款支付宝归属人：卫玉珍
```

对应字段（已内置在 `config/parse_rules.yaml`）：

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| 产品 / 规格 | 群消息（规格可从截图补） | 产品为必填，用于判断「这条消息是不是订单」 |
| 收货人 / 手机号码 / 地址信息 | 群消息 | 地址支持标签「地址信息」「收货地址」等 |
| 备注 | 群消息 | 下单备注等信息，推单信息里会带出来 |
| 售价 | 群消息（可被截图成交价补充） | 群消息优先，截图不覆盖已有值 |
| 出货闲鱼号 | 群消息 | 谁在卖，用于按账号拆账 |
| 回款支付宝归属人 | 群消息 | 钱到谁账上，资金归属维度 |
| **订单号** | **订单截图 OCR** | 群消息里没有，只在截图「订单编号」里 |
| 买家 / 成交价 / 运费 | 订单截图 OCR | 截图里的补充信息 |

> **重要**：订单号只存在于截图里。不开启 OCR 时订单仍会归档（订单号自动填 `AUTO-<消息ID>` 并标记
> 「待确认」），人工在订单详情页补上订单号即可；开启 OCR 后这一列会自动填好。

## 快速开始

```bash
cd xianyu-order-hub

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # 填入飞书应用凭证
python -m app.cli init    # 初始化数据库（已有库会自动补新增字段）
python -m app.cli serve   # 启动，打开 http://127.0.0.1:8000
```

没有飞书凭证也能先体验解析效果：

```bash

```

## 开启截图 OCR（推荐）

截图里含订单号，建议开启，否则订单号需要人工补。

**本机 tesseract（离线、免费，当前 .env 已按此配置）**

```bash
brew install tesseract                                    # 引擎
# 中文简体语言包（brew install tesseract-lang 全量安装较慢，可只装这一个文件）
curl -L -o /usr/local/share/tessdata/chi_sim.traineddata \
  https://cdn.jsdelivr.net/gh/tesseract-ocr/tessdata_fast@main/chi_sim.traineddata
tesseract --list-langs        # 应能看到 chi_sim
```

`.env` 中：

```bash
OCR_PROVIDER=tesseract
OCR_LANG=chi_sim+eng
# OCR 前灰度并放大的倍数（关键：截图小字必须放大，否则订单号会缺字）
OCR_UPSCALE=2
```

**实测数据**（同一张 499×1080 的闲鱼订单截图）：

| 预处理 | 订单编号识别结果 |
| --- | --- |
| 原图直接识别 | `33169016` … `47870`，**中间丢 6 位** |
| 灰度 + 放大 2~4 倍 | `3316901665047047870`（完整），耗时约 0.4 秒/张 |

> 因此 `OCR_UPSCALE` 不要设成 1。识别率参考：订单号、金额、收货地址较稳；
> 商品规格、买家昵称等小字可能有残缺（解析规则已做噪声过滤，宁缺勿错），
> 关键字段建议在订单详情页扫一眼。

**自建或第三方 OCR 服务（识别率更高）**

```bash
OCR_PROVIDER=http
OCR_HTTP_URL=http://127.0.0.1:8868/ocr    # POST multipart，字段名默认 image
OCR_HTTP_FIELD=image
OCR_HTTP_TEXT_KEY=text
```

也可先用 `OCR_PROVIDER=none`，之后随时改成 `tesseract`/`http` 并对历史订单点「重新解析」补数据。

## 订单截图如何归属到订单

- 截图消息会挂到 **时间窗口内最近的一条订单文本** 上；若截图先发、文本后发，则向后找最近的文本
  （窗口默认 120 秒，`IMAGE_FOLLOW_WINDOW_SECONDS` 可调）
- 图片下载到 `data/media/年月/`，订单详情页可查看原图与 OCR 结果
- OCR 文本参与字段解析，但**群消息优先**，不会被截图覆盖
- 群里**只发截图、没发模板**时也能独立建单：下载 → OCR → 判定为订单截图 → 归档建单

### 补发的订单截图（过窗口也能补进去）

模板消息先到了但没截图 → 订单先落成临时编号（`TMP-…`）并回群催图；发送人后来补发的截图，
哪怕超过了配对窗口，也会**按收货人认出属于哪一单**并回填进去：

- 认单依据：收货人手机号 → 收货人姓名（都对不上就不认），产品名辅助加分；只对
  `SCREENSHOT_BACKFILL_DAYS`（默认 7）天内、**还没有截图**的订单回填
- 回填内容：截图归档到该订单、OCR 出来的字段只补空缺（订单号 / 成交价 / 收货信息等），
  临时编号自动升级成截图里的真实编号，原临时编号保留在 `temp_order_no` 备查
- 认不出来的图按老规矩过滤（不落盘），并在消息页写明原因；开关 `SCREENSHOT_BACKFILL_ENABLED`

### 手动维护订单截图（订单详情页）

群里漏发 / 发错截图时，订单详情页「订单截图」区可以直接**上传或更新**：

- 上传后重新 OCR 解析，把**订单编号、成交价、收货信息**等补全到订单；临时编号 `TMP-…`
  会升级成截图里的真实编号（真实编号已被别的订单占用则自动合并）
- **上传前先校验收货人一致性**：截图解析出的收货人 / 手机号与本订单对不上，直接拒绝并提示
  **「订单截图上传不对，请重新上传」**，图不落盘、订单不动（订单本身没维护收货信息时不拦）
- 订单已有的截图会被**最新一张替换**（旧图与旧商品图一并清理），并按新图重裁商品缩略图
- 只更新截图能提供的字段；**成本 / 供应商 / 出货闲鱼号 / 回款归属人 / 备注**属于人工维护口径，
  不会被截图覆盖；支持 png / jpg / webp / bmp / gif，单张 15MB 内
- 没启用 OCR（`OCR_PROVIDER=none`）时也能上传，只是无法自动解析字段，页面会说明

## 订单状态（新建 / 已推单 / 已发货 / 已撤单 / 已退单）

订单从群里同步进来之后，状态跟着业务动作自动走，列表与详情页都能一眼看到走到哪一步：

| 状态 | 什么时候变成它 | 说明 |
| --- | --- | --- |
| **新建** | 飞书群同步订单、归档出订单记录 | 等待运营处理（补全成本 / 供应商后推单） |
| **已推单** | 运营处理完转账等事项，复制订单信息同步给上游（供应商） | 复制推单文案即自动标记，记录推单时间 |
| **已发货** | 上游返回物流单号，运营把物流信息更新到订单 | 在「供应链推单」或订单详情填物流单号即自动标记，记录发货时间 |
| **已撤单** | 还没发货前，卖家或运营把订单撤回 / 撤掉 | 群里撤回订单消息会自动置为已撤单；也可在订单详情手工改。只留档，不参与统计与后续流程 |
| **已退单** | 未发货时群里同步退单 | 自动标记并提醒同步上游拦截；**已发货的退单请求不受理** |

关于退单的口径：**未发货的退单才受理**（标记已退单 + 同步上游拦截）；
**已发货要求退单则不同意** —— 页面直接提示「已发货，不同意退单：请让用户拿到商品后再退，
收到货后走退货退款流程」，订单状态保持「已发货」，退单处理状态记为「已发货无法拦截」；
等用户确实退回、退款完成（处理状态选「已退款」）后才落到「已退单」。

状态流转会自动校验，不允许的跳转会直接提示原因（例如：已发货不能退回「已推单」、
已撤单不能再推单、标记已发货必须先填物流单号、「新建」不能手工改回）。

## 资金结算（发起人 / 供应商）

订单归档后自动生成两条结算流水，钱跟着订单走（补成本 / 改售价后流水金额自动同步）：

| 结算类型 | 方向 | 金额口径 | 结算对象 |
| --- | --- | --- | --- |
| **发起人结算** | 运营应收（对方转给运营） | 买家实付（有成交价取成交价，否则取售价） | 订单发送人（谁在群里发的单，货款先进谁账户） |
| **供应商结算** | 运营应付（运营付给对方） | 采购成本 + 运费 | 上游供应商 |

两者差额再扣平台手续费就是这一单的**预计毛利**。**撤单 / 已受理的退单不再结算**，
对应流水自动置为「已作废」只留档；「已发货无法拦截」的退单未受理，订单照常结算。

页面能力（左侧导航「资金结算」）：

- **按笔 / 按天 / 按月**三种聚合：按笔看每一单的应收应付，按天 / 按月看每一天、每个月要结算多少；
- 筛选：结算类型、结算对象、结算状态（待结算 / 已结算 / 已作废）、日期范围、订单号模糊搜索；
- 结算操作：行内「标记已结算」单笔核销、勾选多笔「结算选中」整批核销、按天 / 按月「整期结算」一键核销，点错可「撤销结算」；
- 顶部看板：待结算发起人应收 / 供应商应付 / 待结算净额 / 本月已结算；成本未维护（¥0）的订单会提醒先补成本；
- 首页「数据总览」也带一块资金看板，点进去直达对应筛选项。

结算流水按订单事实自动生成与校正（服务启动时也会把历史订单补一遍），不需要手工建账。

## 群消息按意图识别（退单 / 撤单，不要求固定格式）

发消息的人不用按模板排版：系统按**动作意图**判断这条消息想干什么，再去找它对的是哪一笔订单。

| 意图 | 触发的话（示例） | 系统做什么 |
| --- | --- | --- |
| **退单** | 此单退、退货、退款、不要了、不想要了、拒收、退回、申请退款… | 关联到订单 → 未发货直接标记「已退单」并提示同步上游拦截；已发货按口径**不同意退单**，回群说明「请让用户拿到货后再退」 |
| **撤单** | 撤单、取消订单、此单取消、作废、不发了… | 关联到订单 → 未发货置「已撤单」（只留档，不参与统计与推单）；已发货不撤，回群提示走退货退款 |
| **撤回消息** | 在群里直接撤回那条订单消息 / 订单截图 | 按被撤回的消息定位订单 → 置「已撤单」，并记录撤单来源与撤单人 |

**怎么找到是哪一笔订单**（按可信度依次尝试，绝不乱动别的单）：

1. 回复 / 引用了某条订单消息 → 直接认那笔；
2. 消息里写了订单号（`订单号 33169016…`）→ 精确匹配；
3. 打分匹配：手机号 / **手机尾号**（只写「尾号 9658」也行）、产品名、收货人、地址，
   再叠加「同一发送人」加权，达到阈值才认定；
4. 兜底：同一发送人最近的在途订单（只有一笔才敢动；有多笔就只标一笔「待人工确认」并回群要订单号）。

**拿不准就不动手**：识别到退单 / 撤单意图但没关联上订单时，回群提示「请补充订单号 / 手机号」，
消息页里保留这条消息的意图与说明（「飞书消息」页新增**意图消息**类别与「退单意图 / 撤单意图」标记），
运营可以随时人工接手。已发货的订单不会被误撤、也不会被退单。

**历史消息保护**：同步历史群消息时，超过 `INTENT_MATCH_DAYS`（默认 7 天）的老消息只有写明订单号
（匹配「很确定」）才会动订单，其余只记录意图说明、等人工核对 —— 避免几天前的一句「不要了」误伤现在在途的订单。

关键词可配置（`.env`，逗号分隔，配置的优先于内置词库）：

```bash
REFUND_KEYWORDS=此单退,退单,退货,退款,拦截
CANCEL_KEYWORDS=撤单,取消订单,此单取消,作废,不发了
INTENT_MATCH_DAYS=7        # 按发送人兜底关联订单时，回溯多少天
CANCEL_NOTIFY=1            # 撤单后是否回群告知处理结果
```

模板消息的口径不变：只看第一行（前 20 字），正文里出现「七天无理由退货」不会被当成退单。

## 只处理模板消息与订单截图

群里消息很杂，系统会归档两类、按意图处理第三类，其余消息入库后标记「已过滤」，不解析、不 OCR、不回执：

| 类别 | 判定方式 |
| --- | --- |
| 模板消息 | 命中平台特征词，且至少解析出一个必填字段（如「产品」）。闲聊即使带「闲鱼」二字也会被过滤 |
| 订单截图 | OCR 文本里出现 `订单编号/订单号/交易单号/平台单号/担保账户` 任意一个，或命中 `SCREENSHOT_KEYWORDS` 中 `SCREENSHOT_MIN_HITS` 个关键词 |
| 意图消息 | 不是订单模板，但说出退单 / 撤单意图（见上一节）—— 用来改已有订单的状态，不会新建订单 |
| 其他 | 文件、表情、系统消息、闲聊文本、非订单图片 —— 不处理 |

处理后**立即回执**告知发送人（默认在群里回复该条消息并 @ 发送人）：

```
✅ 已收到并处理，订单已归档
订单号：3316901665047047870
产品：雷鸟 32U8A Pro / 31.5英寸
金额：售价 ¥2599.00
收货：腾飞 183****9658
详情：https://你的域名/orders/7
```

配置项（`.env`）：

```bash
NOTIFY_MODE=reply          # reply=群内回复并@发送人 | direct=私信发送人 | off=关闭
NOTIFY_WITH_LINK=1         # 回执里附带订单详情链接
SCREENSHOT_KEYWORDS=订单编号,订单号,成交价,实付,商品总价,运费,买家,收货,闲鱼,发货
SCREENSHOT_MIN_HITS=2
```

「飞书消息」页可按类别（模板消息 / 订单截图 / 其他）筛选，每条消息显示类别、解析状态、回执状态；
回执失败或未发送时，可点「补发回执」手动重发。

## 适配模板变化

规则文件：`config/parse_rules.yaml`，也可以在 Web 端「解析规则」页在线编辑并测试，保存即生效。

解析优先级：`patterns(群消息)` → `labels(群消息)` → `ocr_patterns(截图)` → `patterns(截图)` → `labels(截图)`

字段定义示例：

```yaml
- key: receiver_phone
  label: 手机号码
  type: phone
  required: false
  labels: [手机号码, 手机号, 电话, 联系电话, 联系方式, 手机]
  patterns:
    - '(?:手机号码|联系电话|手机号|电话)[:：]?\s*([0-9\-\+\s]{7,20})'
```

字段 `type` 支持：`text` / `int` / `money` / `phone` / `datetime` / `address`。

**模板变了怎么办**：把群里真实的消息（有截图就加上 OCR 文本）粘到「解析规则 → 规则测试」，
看哪个字段没出来，把新的叫法加进 `labels` 即可，不需要改代码。

> 订单号缺失时自动生成 `AUTO-<message_id>` 并标记待确认；同一平台 + 订单号重复的消息会自动合并，
> 只补全空缺字段，不会覆盖已人工修改的内容。列表页可勾选后「标记为已确认」批量清理待确认队列。

## 飞书接入

### 1. 创建应用与权限

在[飞书开放平台](https://open.feishu.cn/app)创建**企业自建应用**，开通权限：

| 权限 | 用途 |
| --- | --- |
| `im:message` | 拉取群历史消息 |
| `im:resource` | 下载订单截图（**必需**） |
| `im:chat` | 读取群信息、列出机器人所在群（也能拿到群成员姓名） |
| `contact:user.base:readonly` | 读取员工真实姓名（**想要显示姓名而不是 open_id 就开这个**） |
| `im:message:send_as_bot` | （可选）回群推送归档/推单结果 |

拿到姓名权限后，系统设置页点「一键补全发送人姓名」即可把历史消息与订单的发送人补成真实姓名
（也可命令行 `python -m app.cli fill-names`）；取不到姓名时页面退回显示 open_id 短串。

把机器人**拉进订单群**。

### 2. 选择消息接收方式

**方式 A：事件回调（实时，推荐）**

- 后台「事件订阅」→ 添加事件 `接收消息 im.message.receive_v1`
- 请求方式：将事件发送至开发者服务器，地址 `http(s)://<你的域名>/feishu/event`
- `.env` 中填写 `FEISHU_ENCRYPT_KEY`（若开启了加密）与 `FEISHU_VERIFICATION_TOKEN`

**方式 B：轮询拉取（无需公网地址）**

- `.env` 中设置 `FEISHU_AUTO_SYNC=1`，服务启动后按 `SYNC_INTERVAL_SECONDS`（默认 300 秒）回溯
  `SYNC_LOOKBACK_MINUTES`（默认 15 分钟）的消息
- 也可以在「飞书消息」页手动指定群和回溯天数补录历史消息

### 3. 配置同步的群

在「系统设置」页可直接看到机器人所在的群，一键加入同步；也可以手动填写 `chat_id`（`oc_` 开头），
或在 `.env` 里写 `FEISHU_CHAT_IDS=oc_aaa,oc_bbb`。

### 语音播报

后台页面在有新情况时会语音提醒（浏览器 Web Speech，无需第三方语音服务）：

| 触发时机 | 默认播报文案 |
| --- | --- |
| 群里同步到一笔新订单 | `你有一笔订单要处理，请实际处理！` |
| 供应商回单物流更新（维护/修改物流单号） | `你有一笔订单供应商已发货，请及时完成店铺发货操作！` |
| 群里同步了退单（此单退 / 退单） | `有退单订单请及时处理拦截！` |

- 开关、音量、语速、音调、朗读语言、音色、重复次数与**三条文案**都在「系统设置 → 语音播报」配置，
  保存写回 `.env` 且即时生效（文案支持 `{订单号}`、`{产品}`、`{供应商}`、`{收货人}`、`{物流单号}` 占位符）；
- 浏览器规定必须有一次用户交互才允许出声：进页面后点一次右下角「🔇 语音播报未开启」按钮即可开启
  （状态记在浏览器本地，刷新后保留），点「试听」按钮可立即试听当前文案。

播报声音的优先级：**自己的录音 → 系统自带人声 → 本机浏览器合成音**，前一档播不出来就自动回落到下一档。

**系统自带人声**：安装包自带三段中文女声提示音（`static/voice/default-*.mp3`），不依赖电脑音色，
所以换电脑、电脑没装中文音色也能响。场景的文案被你自己改过时会自动跳过自带录音（录音是固定一句话，
读不了改过的文案），改用合成音朗读 —— 设置页「没录音时用什么声音」可整个关掉，回到旧的纯合成音策略。

**用自己的录音播报**：在「系统设置 → 语音播报 → 用我自己的录音」给三个场景各上传一段自己录的提示音
（mp3 / wav / m4a / aac / ogg / webm / flac，单个 ≤10MB），传了就播你的声音，删除即回落；
文件存 `MEDIA_DIR/voice`（容器部署挂在 media 数据卷里，重建不丢）。
录音是固定一句话，读不出 `{订单号}` 这类变量：要读出动态内容的场景不要给它上传录音（留空即可）。

### 重复订单去重

群里可能把同一笔订单重复发一遍（误发 / 补发）。系统按「产品 + 收货人 + 手机号」认出同一单：

| 情况 | 处理 |
| --- | --- |
| 内容完全一致 | 不重复归档、不重复推单、不重复播报；群里 @ 发送人回一条「已收到过，内容没有变化，未重复归档」，消息标记为「重复未变」 |
| 内容有变更（改售价/地址等） | 按正常流程处理：更新订单字段 + 正常回执 + 语音播报 |

相关配置（`.env`）：`ORDER_DEDUPE_DAYS`（默认 30，回溯多少天内比对；设 `0` 只按订单号认单）、`DEDUPE_NOTIFY`（是否回群提醒「已收到过」）。

### 逆向退单

群里把退单信息按订单模板发出来（**第一行**带 `此单退` / `退单` / `退货` / `退款` 等关键词，其余字段同正常订单）：

```
此单退
产品： 徕芬吹风机LF03 深灰色
收货人： 蓝曼波
手机号码： 15872093763
...
```

- 按 手机号 / 产品 / 收货人 自动匹配原订单并标记为退单（匹配不到就新建一笔退单订单待人工核对）；
- 订单列表整行红色高亮 + 红色「已退单 · 待拦截」徽章，列表顶部提示待拦截数量；
- 详情页顶部醒目红色告警 + 「退单拦截处理」卡片：可维护 待拦截 / 已拦截 / 已发货无法拦截 / 已退款 与处理备注（记操作日志）；
- 语音播报「有退单订单请及时处理拦截！」，群里 @ 发送人回一条拦截提醒（已出物流单号的会提示立即联系供应商拦截）；
- **退单订单不再参与推单给供应商**，避免继续发货。

相关配置（`.env`）：`REFUND_KEYWORDS`（关键词，逗号分隔）、`CANCEL_KEYWORDS`（撤单关键词）、
`REFUND_MATCH_DAYS`（默认 90，回溯匹配原订单的天数）、`INTENT_MATCH_DAYS`（默认 7，按发送人兜底关联订单的天数）、
`REFUND_NOTIFY`、`CANCEL_NOTIFY`。

退单 / 撤单**不要求按模板排版**：一句「这单不要了」「麻烦撤单」也能识别并按意图改订单状态，
详见上面的《群消息按意图识别（退单 / 撤单，不要求固定格式）》。

### 时间口径（重要）

全站统一 **东八区（北京时间）**：数据库里的系统时间字段（`created_at / updated_at / pushed_at / notified_at` …）
都直接写北京时间，页面按原值展示，不再做二次换算；飞书消息时间由毫秒时间戳按东八区换算。
业务代码统一用 `app/timeutil.now()`，不要用 `datetime.utcnow()`。

老库升级时会做一次性平移（`schema_migrations` 里记录 `2026-09-beijing-time`）：
所有系统时间字段 +8 小时，飞书消息时间（`raw_messages.msg_time`、`orders.msg_time`、`orders.ordered_at`、
`sync_states.last_message_time`）本来就是北京时间，不会被改动。容器同时设置 `TZ=Asia/Shanghai`。

成本没维护（=0）时毛利会虚高，因此订单列表顶部、订单详情顶部与数据总览都会红色提醒，
成本为 0 的单元格与「编辑订单 → 成本」输入框（红底加粗）也会标红，提示推单人员及时补全。

订单**没有指定供应商**时（空值或写着「未指定」），详情页推单模块会给最醒目的红色告警：
整块红边高亮 + 大号红字提示 + 红底加粗 chip，复制推单文案前还会二次确认，避免推错供应商、
「今日第 x 单」算错供应商。

物流单号在「供应链推单 → 已推单记录」里维护（订单详情也能改，但详情页改动不会发群）：
保存后会以**回复原订单消息**的形式发到群里并 @ 订单发送人，同时记录最近同步时间；
系统设置里把下发方式关成「关闭」时只保存不同步，页面会提示。

> @ 的是**这笔订单的原发送人**：订单会记住下单那条消息与发送人，机器人自己的回执 / 转发消息
> 不会覆盖它。万一订单来源不是群成员消息（拿不到人员标识），保存提示里会明确写出
> 「未 @ 到原发送人」，提醒手动 @ 一下。

推单导出的列：批次号、订单号、出货闲鱼号、产品、规格、数量、收货人、手机号码、地址信息、买家、
售价、成本、回款支付宝归属人、备注、供应商单号、运单号。

单笔推单文案（订单详情页顶部「推单信息」，一键复制）：

```
产品：亚朵四代单枕头
收货人：贲
手机号码：14790021215
地址信息: 安徽省 滁州市 琅琊区 清流街道 凤凰湖畔18栋

备注：要黑色，尽快发货

成本价：60
是否转账：未

今日（9/25）周五 第1单，烦请及时发货！
```

「今日（9/25）周五 第 x 单」按供应商分别计数（东八区自然日），带上日期与周几避免跨天对账歧义；复制即视为已推单，订单自动标记「已推单」并记录推单时间，
该动作同样记入操作日志。

### 导入历史订单（付款登记表）

运营手上的登记表（xlsx：`日期 / 供应商 / 产品 / 型号 / 颜色 / 成本价 / 出货价 /
出单账号 / 带教归属人 / 付款金额`）可以直接导成系统订单 —— 列名换说法
（`售价` / `出货闲鱼号` / `归属人`…）也能认，默认只预览，加 `--apply` 才写库：

- 订单号落 `HIS-年月日-序号`：登记表没有截图可补，用 `HIS-` 而不是 `TMP-` 临时号，
  不会被当成「等截图补单号」去群里催图；
- 表格日期作为出单日 `ordered_at`，统计趋势与资金结算都按这一天归；
- 已付款（付款金额 > 0）记为「已推单 + 已转账」，应付流水自动核销；付款金额 0 记「未转账」，
  留给运营按实际付款情况核销；
- 导入后按系统口径生成「公司自营应收 / 公司自营应付」两条结算流水，与群里归档的订单一致；
- 同一份文件重复导入不会重复建单（按 日期 + 出单账号 + 产品 + 售价 + 成本 判重）。

## 公网部署与数据持久化

### 架构

```
互联网 → Caddy(443，自动 HTTPS) → app(8000，单进程) → PostgreSQL 16
                                        ↓
                                  media 卷（订单截图）
```

| 数据 | 存放位置 | 持久化方式 |
| --- | --- | --- |
| 订单/消息/推单批次 | PostgreSQL | `pgdata` 命名卷 |
| 订单截图 | `data/media` | `media` 命名卷 |
| 解析规则 | `config/parse_rules.yaml` | 代码内（改完随镜像发布） |

镜像本身不含任何数据，`docker compose down` 不会删卷（只有 `down -v` 会，慎用）。

### 方式一：Docker Compose（推荐）

服务器要求：1 核 2G 以上、80/443 端口可从公网访问、已装 Docker。

1. 域名解析到服务器，例如 `order.example.com`
2. `.env` 里补充：

```bash
DOMAIN=order.example.com          # Caddy 用它自动申请证书
POSTGRES_PASSWORD=换成强密码
PUBLIC_BASE_URL=https://order.example.com
ADMIN_USERNAME=admin              # 后台管理员账号（首次启动自动建号）
ADMIN_PASSWORD=换成强密码          # 留空则用默认密码 xianyu2026，登录后请尽快修改
```

后台账号：默认管理员 `admin` / `xianyu2026`，登录后在「用户管理」创建子账号、重置密码、停用账号；
「解析规则」「系统设置」「操作日志」「用户管理」仅管理员可见，子账号只能看业务页面。
账号格式：3-20 位、字母开头、可用字母数字下划线；密码 8-32 位且必须含字母和数字。
后台所有写操作（编辑订单、推单、改配置、改账号等）自动记入「操作日志」，密码字段不落日志。

3. 启动：

```bash
docker compose up -d --build
docker compose logs -f app        # 出现 Application startup complete 即成功
```

> app 的 `DATABASE_URL` 由 compose 按 `POSTGRES_PASSWORD` 自动注入，`.env` 里的那行会被覆盖。

4. 飞书开放平台把回调地址改成 `https://order.example.com/feishu/event`

### 腾讯云轻量应用服务器（一键脚本）

镜像选「Docker CE」即可，1 核 2G 起步。

1. 腾讯云控制台 → 轻量服务器 → 防火墙，放行 `8000`（走 HTTPS 再放行 `80`、`443`）
2. 本机上传代码：

```bash
rsync -av --exclude '.venv' --exclude 'data' --exclude '.git' --exclude '.env' \
```

### 接上渔货栈（渔货栈，可选）

两端跑在同一个进程、同一个端口：渔枢系统在 `/`，渔货栈（渔货栈那套 `src/`）在 `/self`（见 `app/hub_bridge.py`，老地址 `/hub/*` 会跳过来）。
要启用它，得让渔货栈连到渔货栈自己的库（`src/` 那套代码用的库）：

1. 在 `.env` 里加一行（库地址 / 账号密码照抄渔货栈那边的环境变量）：

```bash
HUB_DATABASE_URL=postgresql+psycopg2://supply_chain:密码@postgres:5432/supply_chain_xiaoyu
```

2. 让 app 也能访问渔枢系统的库：渔枢系统的库只在它自己那套 compose 的网络里可见，
   `docker-compose.yml` 里的 app 已经挂了 `scx_net`（指向渔枢系统的网络，名字用 `docker network ls` 确认）；
   两边不在一起部署时改成能连到的地址即可。

3. 把渔货栈的账号迁进统一用户表（跑一次就行，重复跑会自动跳过已迁的）：

```bash
docker compose exec app python scripts/migrate_hub_accounts.py --dry-run   # 先看会迁哪些
docker compose exec app python scripts/migrate_hub_accounts.py
```

> 不配 `HUB_DATABASE_URL` 就当成没接渔枢系统：渔枢系统一切照常，`/self` 会提示未启用，不会启动报错。
> 没备案就先用 `http://服务器IP:8000`，或选择香港/海外地域。

### 订单数据备份（应用内置）

应用每天北京时间 **03:00** 自动把订单表导出成 JSON 快照（`data/backups/orders_年月日_时分秒.json`），
只保留最近 **7 天**，超期自动删除；后台「数据备份」页可查看 / 下载 / 手动备份 / 删除。

```bash
.venv/bin/python -m app.cli backup              # 手动跑一次并清理超期文件
```

相关配置（`.env`，也可在「系统设置」页查看）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `BACKUP_ENABLED` | `1` | 关闭后不再自动备份 |
| `BACKUP_DIR` | `data/backups` | 备份目录（Docker 里挂了 `backups` 卷，重建容器不丢） |
| `BACKUP_HOUR` | `3` | 每天几点跑（北京时间 24 小时制） |
| `BACKUP_KEEP_DAYS` | `7` | 备份保留天数 |

> 这是**订单数据的逻辑备份**，与下面 `scripts/backup.sh` 的整库备份互补：
> 前者随时可下载核对，后者用于整库恢复。

### 备份与恢复

```bash
./scripts/backup.sh                 # 手动跑一次：数据库 + 截图，保留 14 天
# 每天凌晨 3 点自动备份
0 3 * * * /srv/xianyu-order-hub/scripts/backup.sh >> /var/log/orderhub-backup.log 2>&1
```

恢复：

```bash
# PostgreSQL
docker compose exec -T db pg_restore -U orderhub -d orderhub --clean < backups/db_20260101_030000.dump
# SQLite
cp backups/db_20260101_030000.sqlite data/app.db
# 截图
tar -xzf backups/media_20260101_030000.tar.gz -C data/
```

建议把 `backups/` 再同步一份到对象存储（脚本末尾预留了 `rclone` 一行）。

### 公网安全（务必做）

| 风险 | 处理 |
| --- | --- |
| 订单含收货人手机号、地址 | 后台需登录才能访问（账号存库、会话 Cookie）；默认管理员 `admin` / `xianyu2026`，部署后请立即改密码 |
| 明文传输 | Caddy / certbot 自动 HTTPS |
| 伪造飞书回调 | `/feishu/event` 免鉴权，但请填 `FEISHU_ENCRYPT_KEY` 与 `FEISHU_VERIFICATION_TOKEN` 做校验 |
| 供应链要打开导出图片链接 | 默认截图也需登录；确需免鉴权时设 `AUTH_PUBLIC_MEDIA=1` |

上线检查清单：

- [ ] 域名解析 + HTTPS 可访问，`PUBLIC_BASE_URL` 已改成 https 域名
- [ ] 后台需要账号密码才能打开
- [ ] 飞书回调地址已更新，发一条群消息能自动入库
- [ ] 备份脚本已进 crontab，且至少成功跑过一次
- [ ] 应用只有 1 个进程（后台同步线程只在单进程跑，多 worker 会重复同步）

## 常见问题

**消息被标记为「已忽略」**：说明必填字段（默认「产品」）没命中。到「解析规则 → 规则测试」粘贴该消息，
补上对应 `labels`/`patterns`，再点「重解析忽略与失败的消息」。

**订单号是 AUTO- 开头**：没开 OCR 或 OCR 没识别出「订单编号」。可开启 OCR 后重新解析，
或直接在订单详情页手工填写（填完记得把「待人工确认」改成否）。

**截图下载失败**：确认应用有 `im:resource` 权限且机器人在群里；失败的截图会保留记录，
可后续「重解析忽略与失败的消息」补图。

**没有公网地址**：用轮询方式（`FEISHU_AUTO_SYNC=1`），或用内网穿透把 `/feishu/event` 暴露出去。
